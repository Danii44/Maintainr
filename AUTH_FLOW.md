# Maintainr Authentication Flow

Maintainr exposes separate `/sign-in` and `/sign-up` entry pages. Both use the secure Manus OAuth session and callback, but each page now sends its explicit authorization intent: `/sign-in` uses `type=signIn`, while `/sign-up` uses `type=signUp`. The OAuth callback upserts the authenticated identity into the `users` table, creating the account on first authentication and updating the existing record on later sessions.

After authentication, the exact role is checked by the protected portal route guard. The backend remains authoritative for role, organization, ticket, and unit scoping; the frontend guard only prevents confusing navigation. A user without the required portal role receives an access message rather than seeing another role’s workspace.

First-time tenants use `/join-unit` after authentication. The tenant enters the six-digit access code generated by a property manager, and the protected onboarding procedure validates the code, binds the account to the correct unit and organization, then allows entry to the tenant portal. The code is never trusted solely from frontend validation; the server verifies its format, ownership, expiration, and organization relationship.

Firebase configuration is intentionally deferred. `FIREBASE_SETUP.md` and `.env.firebase.example` document a later, user-configured migration path without changing the current OAuth, database, or S3-compatible storage behavior.
